# SHŌEN — Samurai Prototype 01

Original, generated Blender geometry for a late-Heian / early-Kamakura-inspired elite foot presentation. The two supplied reference images guide silhouette and palette; they are not treated as verified historical diagrams. No downloaded character, paid mesh, or third-party animation is used.

## Reproduce

From the repository root:

```sh
python3 tools/samurai.py source
python3 tools/samurai.py validate-source
python3 tools/samurai.py import
python3 tools/dev.py build
python3 tools/samurai.py test
python3 tools/samurai.py lab --camera close --soldiers 100
python3 tools/samurai.py benchmark --camera wide --soldiers 1000
```

Blender: `/Applications/Blender.app/Contents/MacOS/Blender`, **5.1.2**. Unreal: installed **5.8.2**. `--engine` or `UE_ROOT` selects the engine root. Blender may require normal macOS access outside Codex's filesystem sandbox. The wrapper records exact commands and logs under `artifacts/samurai-prototype/local/`; it refuses to start Unreal while another `UnrealEditor` process is running. Close other editor/game sessions normally first. Do not run Blender renders, builds or other heavy work during performance sampling.

The source script contains all geometry, UV, material, skeleton, animation and export operations. The saved `.blend` opens with named modular parts, packed atlas textures, and a studio camera. Runtime duplicates are in a hidden EXPORT collection. The validator reopens the file independently and checks object presence, UVs, finite coordinates, normalized skin weights, required bones and animation actions.

## Source and runtime distinction

- **Source:** 18 named components, including an underlying human body, clothing, separate armor sections, yumi, tachi, sheath, quiver and arrows. Weapons have explicit source pivots and `attachment_bone` properties. Armor stays rigid on designated bones; the elbow cloth blends between arm bones. Finger bones are present but this pass does not animate individual fingers.
- **Conventional skeletal asset:** combined clothing/armor/body, **one material section**. Covered anatomy is removed from the export copy, while the editable body retains it. Handheld equipment and quiver remain separate imports. Weapon attachment uses inverse reference-bone rotation because the exported prop axes remain world aligned.
- **Formation asset:** combined equipped static mesh, three imported reduced LODs. Each LOD has one section, referencing its own VAT material instance and texture pair. Each formation owns three dynamic material instances but draws only its active LOD's section. It does not create per-soldier Actors or skeletal components.
- **Animation:** the formation's vertex animation textures (VAT) contain actual evaluated positions/normals from the same Blender rig, at 24 samples for each of idle, walk and a simple guard/thrust test. Time is offset per instance. The conventional skeletal body retains the full FBX animation clips.

`asset-manifest.json` records actual source/export triangles, bones, per-component counts, VAT dimensions, axis mapping and pivots. `source-validation.json` is generated by the reopen check. Final Unreal counts and performance are recorded under `artifacts/samurai-prototype/` after import and testing.

## Export / import contract

- Blender metres, +X character left, -Y forward, +Z up. Armature has one `root`; familiar humanoid names plus armor and weapon pivots. This is an original skeleton with an explicit future retargeting requirement, not an assertion of drop-in Manny/Quinn compatibility.
- FBX: selected objects only; no leaf bones; all scale stored in FBX units; scene-axis transform disabled; Z up/-Y forward metadata; no mesh material/texture auto-import. Animations export one action per file with baked keys and no key reduction.
- Unreal legacy FBX import: `convert_scene=False`, `convert_scene_unit=True`. Local points become `(x,-y,z)*100` cm. Raw imported mesh faces +Y, corrected by **one -90° component/instance yaw** to SHŌEN's +X forward. VAT offsets use the same raw local axes. Full-precision UV1 preserves vertex lookup addresses through FBX's vertex reordering.
- UV0: shared 2K BaseColor, normal, ORM atlas. OpenGL normal green is flipped on Unreal import. Fine lacing, cloth motif, metal grain and leather detail are texture treatments. No alpha-cutout hair/cord layers.
- UV1: vertex lookup into a specific LOD's VAT texture. Three 24-frame clips are packed vertically. Unreal's flipped V coordinate is accounted for by subtracting the frame offset. Baked normals are sampled at vertices then interpolated, so pixels never sample an interpolated vertex ID.
- VAT EXRs: losslessly ZIP-compressed half-float source, non-sRGB HDR import, nearest filtering, no mips, no streaming. Ordinary atlas textures keep normal mipmapping. The static control material removes VAT sampling entirely for a meaningful animation-cost comparison.
- Automatic skeletal LODs and the imported crowd LODs are initial feasibility reductions; no manually perfected distant faces/ornament.

## Current visual limitations

This is a parametric prototype, with a more stylized face, simplified cloth folds and more regular armor/lacing than the supplied reference. It is not a photorealistic scan or final AAA character. Individual fingers, facial motion, cloth simulation, hit/death animations, weapon draw, bowstring pull/release and mounted use are outside this pass. The attack clip proves rig/armor motion; it is not a finished sword strike or archery attack.

Reference match is judged from actual Blender and Unreal captures. Helmet, broad shoulders, flared skirt, bow and restrained dark-blue/red/brass palette are the intended tactical identifiers. Historical accuracy of decorative details is not certified.
